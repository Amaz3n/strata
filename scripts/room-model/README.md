# Offline specialist-model screening

These scripts are experiment adapters, not application code. They load local weights and local images, run CPU inference, and emit masks, overlays and unreviewed region polygons. They make no network calls and perform no database writes. Do not use their pixel areas as takeoff quantities.

## Setup

Use Python 3.12 in a temporary virtual environment, then install `requirements.txt` there. The full resolved environment for the initial run is in `requirements-lock.txt`. Keep weights and customer input/output outside the repository.

The evaluated weights are published by:

- [Yytsi/floorplan-to-3d-walls](https://huggingface.co/Yytsi/floorplan-to-3d-walls): `best.safetensors` and `config.yaml`. SHA256 of tested weights: `d7f6a0fd06e2931aecfc8c4849192c5e153701578026efc78d9a6246731a8d6c`.
- [zcemycl/TF2DeepFloorplan](https://github.com/zcemycl/TF2DeepFloorplan): the README's `tflite.zip`, containing `model.tflite`. SHA256: `9192751390189bc959f1233abcb54872dc78ce6933c902d4e2c487d628d767a4`.

Do not deserialize pickle checkpoints or execute downloaded model repository code. The first adapter uses the installed `segmentation-models-pytorch` architecture and a strict safetensors state-dict load. The second executes the TFLite graph with TensorFlow's interpreter. Neither installs a model into Arc.

Licensing is not cleared for production: Yytsi labels its model MIT but identifies CubiCasa5K training data; that dataset carries noncommercial terms. TF2DeepFloorplan publishes its code under GPL-3.0; weight and data terms also need review before product use. These evaluations do not establish redistribution rights.

## Commands

```sh
python scripts/room-model/evaluate.py \
  --image /path/sheet.png --weights /path/best.safetensors \
  --config /path/config.yaml --feet-per-pixel 0.05333333333333333 \
  --output /tmp/room-model/full

python scripts/room-model/evaluate_tflite.py \
  --image /path/sheet.png --weights /path/model.tflite \
  --feet-per-pixel 0.05333333333333333 \
  --crop 955 280 1985 1460 --output /tmp/room-model/crop
```

Scale belongs to the actual input image. The initial source PNG was half the original 5400x3600 raster dimensions, so its feet-per-pixel is twice the stored full-resolution calibration. Crops preserve the original sheet origin in exported polygons. The crop is manually selected, not automatic plan detection.

`evaluate.py` uses RGB, ImageNet normalization, zero normalized letterboxing and the published 512 input size. `--size 1024` is an explicit exploratory resolution variant, not the trained input size. The TFLite model uses the publisher's square resize, RGB /255 and bilinear logit restoration. Output heads are identified by channel count (3 boundary classes, 9 room classes), not assumed tensor order.

Both scripts extract enclosed components from predicted barriers without fabricating missing walls. Components touching the image/crop edge and components smaller than 12 SF are excluded and counted in the report. The TFLite path additionally requires a majority non-background room-type prediction. It does not implement the publisher's optional morphological postprocessor: this is raw-boundary screening. The initial failure is also directly visible in near-absent wall masks, not only in the region-count filter.

Polygons preserve holes; the earlier room benchmark rejects holes until that scoring feature is implemented. Do not drop holes to make a candidate pass. Per-pixel areas are diagnostic values, not scored measurements. No reference labels or accuracy claims are generated by these scripts.

## Initial screen

On the selected real development sheet, full-sheet and manually cropped runs of both models returned zero enclosed regions above the screening threshold. The Yytsi crop at 1024 also returned zero. Visual inspection showed weak/incomplete walls and misclassification of wall runs as openings.

As an execution sanity check, the same TFLite adapter returned four plausible room regions on the author's `resources/30939153.jpg` example. That run used an arbitrary scale only to exercise filtering; its areas have no physical meaning. This is a positive control for execution, not a ground-truth accuracy test. Some spaces still remained undetected.

The Yytsi training renderer explicitly removes nonstructural SVG elements (text, furniture, dimensions) before rasterizing. That input differs substantially from construction sheets. Neither the publisher's validation score nor this one-sheet screen supports a general accuracy claim.

This screen rejects these two off-the-shelf weights for immediate integration. It does not rule out other models, fine-tuning on representative drawings, or commercial engines.
