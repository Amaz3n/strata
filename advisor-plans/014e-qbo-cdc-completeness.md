## Scope and steps

1. Extract a typed CDC response parser behind the existing ingestion facade. Read every response group, validate envelopes, faults, arrays and identities, and distinguish a documented mostly empty response from malformed data. Count raw objects across groups before dedupe. Validate pagination/count hints where supplied; contradictory/truncated metadata never proves completeness. Missing/invalid entity timestamp can be durably queued for investigation, but cannot authorize cursor advancement. Preserve provider timestamp precision and canonical webhook identity. Explicit deletion records remain deletion events; absence from a page is never a deletion.
2. Capture a safe checkpoint before the provider request begins. Advance at most to that instant after complete validation and durable intake, never to the post-fetch wall clock or a future entity timestamp. An already-future cursor produced by historical code also needs explicit durable recovery handling; silently retaining an unreachable future boundary can keep skipping current changes. Preserve overlap, duplicates, terminal work, and nondecreasing compare-and-swap semantics. Inspect the existing SQL cursor function: replacing stale settings must not regress a concurrent poll or erase unrelated settings. Test interleaved old/new poll completion against exact SQL.
3. A combined result at the cap is incomplete even if reported counts equal the cap. Retry supported entity-specific CDC queries from the retained checkpoint, under inherited budgets. An individual response strictly below the cap with valid count/envelope evidence can prove that entity's catch-up. Do not advance past a full-cap timestamp group, or use the latest active timestamp while deletions are returned later. Record per-entity progress when needed so a bounded worker can resume without repeatedly starving the last entity. A global checkpoint must remain at the oldest unresolved entity boundary. Any change to the provider result contract must retain existing callers and truthful counts.
4. If a single entity remains saturated, timestamps are ambiguous, the original boundary is outside the provider window, or a complete scan cannot be proved, persist recovery-required evidence. Preserve the original lost-window boundary, affected entity types, reason and resumable recovery/run identity. A later short successful CDC poll must not erase an unresolved historic gap. Use an additive service-only migration/RPC only where existing storage cannot express these invariants; generate locally with `supabase migration new`. Preserve Q02 credential privileges and Q03 intake permissions. Records belong to the company and organization, not a generic payment receipt.
5. Provide a bounded full reconciliation/import recovery path using existing identities and import contracts. Its progress and unresolved gaps must survive invocation failure. Confirm remotely missing mapped objects through supported entity reads; a failed query or incomplete enumeration cannot authorize deletion or money mutation. Use reviewed correction/conflict behavior for posted facts. Define what evidence proves enumeration plus changes occurring during it; if the API cannot provide it for a scenario, leave that scenario explicitly unresolved rather than marking a scan complete. Expose recovery evidence through the existing operational result/health path; the Q10/Q11 UI must consume it. Full Q04 acceptance includes this recovery path, even if the safe parser/checkpoint slice lands first.
